# rclone und Nextcloud

Für das **AW4.0**-Projekt brauchten wir jede Menge Speicher — das habe ich bereits in vorigen Artikeln beschrieben (Ceph-Cluster und AW4.0). Jetzt stellt sich die Frage, wie man die Daten gut synchronisiert bekommt.

Klar kann man ein Ceph direkt als Volume in Linux einbinden — das mache ich auch manchmal. Aber ich benutze auch gerne **rclone**, insbesondere dann, wenn ich die Daten auch mit anderen Leuten teilen möchte (über Nextcloud).

## 1. App-Passwort in Nextcloud anlegen

Nicht das normale Konto-Passwort verwenden, sondern ein dediziertes App-Passwort:

1. Oben rechts auf den **Avatar** klicken → **Settings**.
2. Zu **Security** wechseln.
3. Ganz unten bei **Devices & sessions** einen App-Namen vergeben (ich habe z.B. `nextcloud` vergeben).
4. Auf **Create new app password** klicken → es erscheint ein **Modal** mit Benutzername und generiertem Passwort.

**Wichtig:** Die Daten dieses Modals verschwinden nach dem Schließen und lassen sich nicht wieder anzeigen — also direkt abspeichern.

## 2. rclone installieren und Remote konfigurieren

rclone installieren, dann die interaktive Konfiguration aufrufen:

```
rclone config
```

Der Vorgang:

1. `n` für **New remote**.
2. **Name** vergeben — das wird das spätere `<cloud-label>` (z.B. `nextcloud`).
3. Als **Storage-Typ** `webdav` wählen (Nextcloud spricht WebDAV).
4. **URL** angeben: die WebDAV-Adresse der Instanz, Form
   `https://<meine-nextcloud>/remote.php/dav/files/<BENUTZERNAME>/`
5. **Vendor** auf `nextcloud` setzen.
6. **user**: der Nextcloud-Benutzername.
7. **pass**: hier das eben erzeugte **App-Passwort** eintragen (nicht das Konto-Passwort).
8. **Advanced config?** → `n`.
9. Übersicht bestätigen mit `y`, dann `q` zum Verlassen.

Ein Test schadet nicht:

```
rclone lsd nextcloud:
```

## 3. Kopieren

```
rclone copy -P <lokaler pfad> <cloud-label>:<ordner in der cloud>
```

Das `-P` (Progress) **nicht vergessen** — sonst sieht man den Zustand des Transfers nicht (keine Fortschrittsanzeige, keine Rate, keine ETA).

## 4. Im Hintergrund laufen lassen (tmux)

Ich benutze das Ganze gerne in einer **tmux**-Session, sodass der Transfer im Hintergrund weiterläuft und ich detachen kann:

```
tmux new -s sync
rclone copy -P <lokaler pfad> <cloud-label>:<ordner in der cloud>
# detachen: Ctrl-b d
# später zurück: tmux attach -t sync
```

So kann die Verbindung zum Server unterbrochen werden, ohne dass der Kopiervorgang abbricht.
